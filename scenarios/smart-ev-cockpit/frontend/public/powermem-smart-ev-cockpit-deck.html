$ diagnose --need memory

AI 应用为什么需要记忆

长期记忆不是聊天记录缓存，而是让应用跨会话、跨用户、跨 Agent 保持连续认知的基础设施。

没有记忆的 AI

  • 跨会话后上下文断裂，无法维持连续认知。
  • 多用户和多 Agent 场景中，经验无法复用。
  • 个性化只能依赖当次 prompt，产品体验反复归零。
  • 长上下文越堆越贵，模型注意力会被无关历史稀释。

有记忆的 AI

  • 把事实、偏好、关系、策略转化为可检索资产。
  • 通过用户、Agent、scope、metadata 管理可见性。
  • 让助手从“会回答”进化为“会记住、会更新、会遗忘”。
  • 把高价值信息从 prompt 中抽离，按需检索、按证据采用。

ADD / UPDATE / MERGE / DELETE

PowerMem 管的是记忆生命周期，不只是新增和搜索。每种操作都要能被审计、回放和业务约束。

ADD从原始输入抽取结构化偏好、事实、关系和策略。
SEARCH按 query、user、agent、tenant、metadata、visibility 找到相关记忆。
UPDATE新事实修正旧事实时更新内容、metadata、scope 或 lifecycle。
MERGE近似记忆合并为更稳定的长期表达，保留 provenance。
ARCHIVE低价值、阶段性、过期记忆退出活跃检索空间。
DELETE用户要求删除或隐私策略要求清理时，产生可审计操作。
RESET面向测试、demo 和回放重建可复现记忆环境。
AUDIT记录 request、selected ids、decision reason、before/after status。

Ebbinghaus 生命周期与遗忘治理

参考原 PPT 的艾宾浩斯遗忘管理：记忆按重要性进入不同层，访问强化会减缓衰减，低价值记忆自动退出活跃空间。

信息输入对话、工具事件、SOA 状态、用户画像和车辆档案进入候选记忆池。
重要性评分综合来源可信度、业务类型、用户反馈、访问频次和隐私等级。
访问强化frequent access 提升 memory strength，使短期偏好有机会进入长期层。
遗忘衰减 / 自动清理低访问、低价值、过期记忆降权、归档或删除。
Working Memory < 0.6 快速衰减 临时上下文、当前 session 目标和一次性任务，适合“再低一点”这类短程指代。
Short-term Memory 0.6-0.8 中等衰减 近期有效事实和阶段性偏好，例如出差期间临时空调温度。
Long-term Memory >= 0.8 慢速衰减 稳定偏好、身份画像、车辆能力边界、安全策略和家庭关系。
R(t) = e^(-t/S)用时间和稳定性建模自然遗忘，旧记忆默认降低检索优先级。
final_score = relevance_score × decay_factor检索时同时考虑相关性、衰减因子、访问强化、权限和 visibility。

智能座舱记忆的五个卖点

PowerMem 把座舱从一次性问答升级为长期记忆、多乘员隔离、能力边界可控、端云协同和 GIS 场景联动。

01 / long-term cockpit memory 座舱真正有长期记忆 记住空调、座椅、驾驶模式、媒体、地点和用车习惯，让用户每次上车都能延续自己的体验。
02 / user actor seat scope 多乘员个性化不串号 用 user_id、actor_id、seat_position 区分主驾、副驾和后排儿童，同一句话也能按人按座位响应。
03 / capability guard 能力边界可控 车辆能力、车型配置和安全策略作为结构化记忆参与判断，避免车机乱答、乱推荐、乱执行。
04 / edge-cloud memory 端云协同记忆：快、稳、可同步 端侧 seekdb 承载高频低延迟记忆，云端保存长期治理副本，支持弱网可用、跨车同步和审计回放。
05 / GIS linked context GIS 联动：位置感和路线感 把用户与地点、路线、POI、充电站和地理围栏关联起来，让座舱在正确位置主动给出服务。
一句话：PowerMem 让智能座舱不仅会回答，还能长期记住、准确区分、守住边界，并把端侧体验、云端连续性和地理场景连接起来。
